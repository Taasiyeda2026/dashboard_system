# מדידות ביצועים למנוע השיבוצים בשרת

ההשוואה בוצעה מול `main` ב־`5e550550`. הנתיב הפעיל מריץ את המנוע בסוכן GitHub
Actions של השיבוצים. ממשק הדשבורד קורא את התכנון השמור. ב־26 בנובמבר, שאילתות
קריאה ב־Supabase מצאו מנוע v38, workspace ברוויזיה 13354, 173 רשומות עם
`needs_recalc`, 13,843 מסלולים תקפים, ללא lease פעיל. רוויזיית המקור הייתה
18293 והריוויזיה המאומתת שנשמרה ב־workspace הייתה 1755.

## ממצאים

- הנתיב ההיסטורי של v28 השתמש ב־lease ל־900 שניות. PR #2120 אימת שקדימות
  `scheduler.yield()` ב־Chromium יכולה להרעיב טיימרים, בנפרד ממחיר הכנת
  הקשר הארצי. הסיבה המדויקת להפסקת הריצה אחרי 50/175 נשארה לא מאומתת.
  יומני Supabase הזמינים הראו שגיאות Warp ו־statement timeout, אך לא זיהו
  פעולה שאפשר לקשור דווקא ל־checkpoint ההיסטורי.
- בנתיב הפעיל, ההחלטה על validation-only התקבלה לאחר טעינת snapshot.
  ה־Edge כבר תוחם את הטעינה ב־preflight משלו, אבל עדיין קורא את הטבלאות
  ומעביר את מטמון המסלולים ל־worker גם כאשר התכנון מעודכן. בצד השרת נמצאו
  שמונה משימות שהושלמו עם ממוצע של 42.9 שניות ומקסימום 98.7 שניות מה־claim.
  שתי משימות נוספות נכשלו עם `57014`. זו תצפית ייצור לפני השינוי, על
  משימות בהיקפים שונים.
- החישוב ב־Edge ליעדי incremental השתמש ב־7 ימים בעוד ה־preflight והוולידציה
  בייצור דורשים 14. הפער יכול לסווג פעילות כטעונה עדכון בלי להעביר אותה למנוע.
- במנוע הפעיל נמצאו יצירה חוזרת של אותם מועדים, מיון שמחשב שוב מרחק ומדדי
  היצע בתוך comparator, בדיקת חלופות מול אותו אוסף עוגנים, ובקשות חוזרות
  לאותו מסלול בית–בית ספר לפי מספר מפגשים. נמצאה גם לולאת microtasks ב־
  `flush()` שיכולה לחסום סיום של I/O ממתין. מסלול התכנון שנמדד אינו קורא לה.

## מדידות

אותו בדק על Node 24.19, עם 175 פעילויות, 24 מדריכים, 35 בתי ספר,
8 מפגשים לפעילות ו־3,422 זוגות מסלולים בזיכרון. הבדק מפעיל את ליבת v38
עם `planningProfile: 'fast'`. הוא אינו כולל Supabase, קריאות רשת, תור GitHub
או זמני שמירה.

| תרחיש | לפני | אחרי | פעילויות שחושבו | קריאות לשירות מסלולים |
| --- | ---: | ---: | ---: | ---: |
| מלא, 175 פעילויות | 281.38 שנ׳ | 86.17 שנ׳ | 175 → 175 | 0 → 0 |
| פעילות אחת שסומנה | 1.06 שנ׳ | 1.02 שנ׳ | 1 → 1 | 0 → 0 |
| שלוש פעילויות שסומנו | 1.92 שנ׳ | 1.50 שנ׳ | 3 → 3 | 0 → 0 |

השיפור בריצה המלאה הוא 69.4%. השהיית טיימר הבדיקה המרבית ירדה מ־3,303ms
ל־468ms. השלב האזורי ירד מ־58.3 ל־35.4 שניות וחישוב בלוקי ההשמה ירד
מ־204.0 ל־32.7 שניות. מספר החלופות שעברו הערכה נשאר 499,968.
חתימת SHA-256 של מזהי הפעילות, הסיווג, המדריך והמפגשים התאימה בכל שלושת
התרחישים. החתימה אינה משווה שדות אבחון או חלופות משניות.

בדיקת NO-OP של בקשת הצוות ב־PostgreSQL 16 מבודד מדדה 2.19ms הלוך וחזור
מאותו מארח. השאילתה החזירה תשובה בלי להוסיף משימה, לשלוח wakeup, לקחת
lease או לטעון snapshot. הנתיב המקורי הכניס משימה וחיכה להרצת GitHub.
בכניסה דרך הסוכן כעת נדרשת קריאת RPC אחת. עבור בקשה קיימת בתור, ה־worker
משתמש ב־probe וב־claim ועוצר לפני טעינת snapshot. קודם הוא היה מבצע גם lease,
snapshot, שתי בדיקות preflight, persist ו־release. ספירת הקריאות היא לפי זרימת הקוד,
בנפרד ממדידת PostgreSQL. בקנה המידה שנמצא בייצור, snapshot היה דורש 28 דפי
מטמון של 500 שורות כל אחד ב־NO-OP. כעת נדרשים אפס. ריצת חישוב עדיין קוראת
את מטמון השרת במנות.

לשחזור מדידת המנוע, הריצו `node scripts/benchmark-planning-runtime.mjs`;
`BENCH_ENGINE_ROOT` מאפשר להפנות לעותק של נקודת הייחוס. יומן ה־worker
כולל זמני שלבים וספירות, נפח טעינת מטמון, עיכוב טיימרים וקצב התקדמות מוגבל.
הבדיקות המבודדות כוללות race על claim, lease לאותו בעלים ולבעלים אחר, takeover,
heartbeat במהלך חישוב, אימות revision ו־checkpoint של מסלול הדפדפן.

## מסירה ובקרה

יש לבדוק את migration `20261126120000_scheduling_agent_claim_fast_path.sql`
ואת שתי פונקציות Edge שעודכנו לפני שילובם. ה־worker עדיין מקבל את חוזה
ה־claim הקודם כאשר ה־migration חסר. ה־migration נבדק ב־PostgreSQL מבודד.
את ההתנהגות הקודמת אפשר לשחזר באמצעות החזרת שלוש פונקציות ה־SQL
מה־migration `20261016000000_scheduling_agent_durable_wakeup.sql`
והחזרת גרסאות הקוד הקודמות במהלך פריסה מתואמת.

נותרו מדידות מקצה לקצה בסביבת staging עם נתונים מייצגים, זיהוי מדויק של
הפסקת הריצה ההיסטורית, צמצום טעינת המסלולים בריצה שדורשת חישוב, ושמירת
checkpoint/resume פעילה בסוכן השרת. התאוששות הסוכן מחזירה את המשימה לתור
והריצה מתחילה מחדש. ה־PR נועד לבקרה כטיוטה. בדיקות הייצור היו בקריאה בלבד.
