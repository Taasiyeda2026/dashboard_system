# אימות סופי ותוכנית פריסה לחשבונות עסקה

בדיקות הכספים המקוריות הורצו מול `a4dc351b`. ענף ה־PR סונכרן עם `origin/main` בנקודה `a5c443b9`. בסנכרון נפתרו התנגשויות בסמני השחרור ובגרסת המטמון בלבד, ושש בדיקות PWA עברו. האימות המקומי משתמש ב־PostgreSQL 17 ב־loopback ובחשבונות סינתטיים. בבדיקת קריאה בפרויקט Dashboard נצפו 35 חשבונות, 141 שורות חיוב, 6 תקבולים ו־47 הקצאות. לכל חשבון שהופק היה מספר. לא הועתקו נתוני החשבונות ל־staging.

בדיקת המיגרציות משווה חשבון שהופק, הפניה ל־PDF, תקבול, הקצאה ויתרה לפני ואחרי כל שש המיגרציות. בדיקת המחיקה מוודאת שהחשבון יורד גם מתוצאת RPC היתרות, תוך שימור התקבול ושחרור ההקצאה.

## תנאי החלטה

- בסביבת הבדיקות הקיימת אומתו המיגרציות על מדגם סינתטי. השוואה על עותק מייצג של נתוני הייצור לא בוצעה.
- חיבורי SharePoint ו־Outlook הקיימים אומתו בקריאה. העלאה ומחיקה בהרשאות האפליקציה ויצירת טיוטה בתיבת המפיק אומתו מול שירותים מדומים. בתקלה בפועל, ייתכן שהחשבון יופק בלי טיוטה, או שמחיקה תישאר ממתינה לאחר שגיאת SharePoint. יש להביא סיכונים אלה להחלטת בעל המערכת לפני אישור הפריסה.

## חלון הפריסה לאחר אישור

1. לקבוע חלון תחזוקה ולהשעות פעולות כתיבה בחשבונות עסקה. לפני המיזוג המאושר להשהות את שתי הפריסות האוטומטיות שמופעלות ב־push ל־main, ולוודא שאין ריצות פריסה או פעולות כספים פעילות. [פריסת Edge](https://github.com/Taasiyeda2026/dashboard_system/actions/workflows/deploy-finance-transaction-accounts.yml) · [פריסת GitHub Pages](https://github.com/Taasiyeda2026/dashboard_system/actions/workflows/deploy.yml)
2. לאמת נקודת שחזור זמינה בתשתית הקיימת ולשמור את SHA הייצור, גרסת Edge, ערך ה־Sequence ומדדי בסיס של סכומים, תקבולים, הקצאות ויתרות. להשוות לפי מזהה בסדר יציב. למזג רק לאחר האישור וכשההשהיה בתוקף.
3. להשוות את יומן המיגרציות של היעד ל־SHA המאושר ולבדוק dry run. שש מיגרציות הכספים הן `20261126131805` עד `20261126133511`, והן מוקדמות ממיגרציית השיבוצים `20261126142551`. אם מיגרציה מאוחרת כבר רשומה ביעד, לבדוק את רשימת המועמדות גם ב־dry run עם `--include-all`. אם הרשימה כוללת מיגרציה מחוץ לחלון המאושר, לעצור ולהסדיר את הפער לפני כתיבה. להחיל את שש מיגרציות הכספים בסדר הגרסאות ולוודא שמדדי הבסיס תואמים, שמונה המספור תקין ושהרשאות RPC ו־RLS תואמות.
4. לפרוס ידנית את Edge מאותו SHA מאושר, ואז את הממשק עם סמני המטמון. לבצע בדיקות קריאה והתחברות מול התשתיות הקיימות. להחזיר את מנגנוני הפריסה האוטומטיים לאחר אימות הגרסאות.
5. לשחרר את ההשהיה באישור בעל המערכת. לעקוב אחר ההפקות העסקיות הראשונות ביומני Edge, SharePoint ו־Outlook ולהשוות סכומים, מספר חשבון ומצב טיוטה. להשעות שוב כתיבה אם מתגלים פערי יתרה או מספור, או כשל חוזר בפעולות Microsoft.

## התאוששות

- אם האימות נכשל לפני שחודשו פעולות הכתיבה, להשאיר את המסך בהשהיה. לתקן או לחזור לגרסאות Edge והממשק שנשמרו רק באמצעות תהליך מתואם עם שחזור DB או מיגרציית התאמה.
- אם כבר בוצעו פעולות עסקיות בגרסה החדשה, להעדיף תיקון קדימה. לפני שחזור לתאם עם כספים את רשימת החשבונות, התקבולים וקובצי Microsoft שנוצרו אחרי נקודת השחזור. לשמור את יומן המחיקות והגרסאות וליישב פעולות לפי מזהה פנימי. שחזור בסיס הנתונים אינו מחזיר קובץ שכבר הוסר משירות חיצוני.
- אם חוזרים להקצאת Sequence, לסנכרן אותה תחת נעילה לערך שאינו נמוך מהמונה החדש או מהמספר הפעיל המרבי ועוד אחד. לא לפתוח כתיבה עד אימות אי־התנגשות בין הגרסאות.
